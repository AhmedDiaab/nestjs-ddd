# Known gaps and open items

An honest, dated review of what this template **does not** do, what is weak in what it does do, and what I'd fix first. Kept in the repo so a team adopting the template inherits the list instead of rediscovering it in production.

- **Reviewed**: 2026-09-19, against `main` (`84e2f4b`), after the idempotency feature landed; re-checked the same day against the pushed repository and its CI.
- **Size at that commit**: 231 source files, ~6,770 lines, 24 runtime dependencies, 68 spec files (56 unit, 9 e2e, 3 live Oracle), coverage floor 87/72/76/87.
- **Scope**: the template itself. Business features built on top are out of scope.
- **How to use it**: before starting a project from this template, walk sections 1 and 2 and decide per row — fix it, accept it, or replace it with your platform's version. Cross items off as you go; delete the ones that don't apply to you.

Terms: [Glossary](glossary.md). Rules the template does enforce: [Architecture overview](architecture/overview.md).

## 0. Closed since the first review

**2026-09-18, first pass**: the `Hello World` scaffolding is gone and `AppModule` is now only a composition root. Correlation ids from outside are validated before they reach the logs, and both the request id and the W3C `traceparent` come back as response headers ([Observability](architecture/observability.md)). Shutdown fails readiness first, keeps serving while the load balancer notices, drains in-flight requests and closes the database pools last ([Operations](architecture/operations.md#graceful-shutdown)). Authentication used to be opt-in per controller; `JwtGuard` is now a global `APP_GUARD` with a `@Public()` opt-out ([guide](guides/add-an-auth-strategy.md)). Metrics, tracing, an outbound HTTP client with retries and a circuit breaker, CI on every pull request and a coverage floor all landed.

**2026-09-18, second pass**: the interface layer is fenced — `src/interface/**` cannot import `@infrastructure` at all, enforced by ESLint and kept honest by `test/unit/layers/interface-fence.spec.ts`. `HealthController` goes through a new `DatabaseHealthPort` instead of reaching for `ConnectionProviderToken`. `GET /health/ready` answers `{status}` only; the per-source topology moved to an authenticated `GET /v1/health/sources` (`@Roles('admin')`), with failing sources logged at `warn`. Domain event delivery states its guarantee in the port JSDoc and counts `domain_events_published_total` / `domain_event_handler_failures_total`, so a handler that always throws is visible on a dashboard; [the outbox recipe](guides/deliver-events-reliably.md) covers events another system depends on. The rate limiter finally has an e2e proving it returns 429.

**2026-09-18, third pass**: the four items the second pass left open are closed. `JobRunner` now keeps a handle on the in-flight run and exposes `whenIdle()` (never rejects); `JobScheduler.stop(timeoutMs)` stops every registered `CronJob` so no new run starts, then waits for whatever is mid-run, bounded by `withTimeout`, logging `scheduler.drain.timeout` (naming the job) on expiry or `scheduler.drained` otherwise. `runGracefulShutdown` calls it through an optional `drainJobs` hook, after `server.close()` and before `closeApp()` — jobs still need the database, and draining them must not delay the HTTP drain the load balancer is waiting on. The drain has its own budget, `SHUTDOWN_JOB_DRAIN_MS` (default 10000ms), kept separate from `forceAfterMs` because the two mean opposite things: one cuts live sockets and wants to be small, the other waits for a batch and wants to be as long as the job needs. `start-service.ps1`'s `$StopTimeoutMs` moved from 15000 to 30000 — the old value was exactly `drainDelayMs + forceAfterMs` with zero slack, so a job drain would have guaranteed NSSM kills the process before the pools close cleanly; the new default follows the written rule `StopTimeoutMs ≥ drainDelayMs + forceAfterMs + jobDrainMs + slack`, restated in [Operations](architecture/operations.md#graceful-shutdown). `@nestjs/jwt` is gone entirely, not merely demoted to `devDependencies`: nothing in `src` ever signed a token, so the three e2e specs that needed one now sign their own HS256 token by hand with `node:crypto` (`test/fakes/sign-jwt.ts`), and [the auth guide](guides/add-an-auth-strategy.md#issuing-tokens) covers what a service that genuinely needs to issue tokens should do instead. `ThrottlingModule` no longer re-exports `ThrottlerModule` — `@nestjs/throttler` already marks its own module `@Global()`, so the export was dead weight proven by mutation; `ThrottlerStorageToken`, which is genuinely load-bearing, is untouched, and `test/e2e/throttling.e2e-spec.ts` still returns 429 unchanged.

**2026-09-18, re-validation**: `feat/oracle-backport` fast-forwarded into `main` (74 commits) and was deleted; `example/tickets` was rebased onto it and passes `pnpm verify` (367 unit, 53 e2e). Re-reading this file against the merged tree turned up three things it got wrong, all now fixed. `test/unit/infrastructure/http/circuit-breaker.spec.ts` built a breaker without injecting a clock, so `blockedForMs()` measured real elapsed time and failed with `999` whenever a millisecond passed mid-test — an intermittent CI failure waiting to happen, not a flaky machine. `docs/guides/write-tests.md` still told readers to sign test tokens with `JwtService`, a package removed hours earlier in the same day's work: anyone following the guide would have hit `Cannot find module '@nestjs/jwt'`. `docs/guides/feature-walkthrough.md` pointed at `git diff feat/oracle-backport..example/tickets`, a branch that no longer exists. The last two are exactly the rot the first opinion below predicts, arriving on schedule.

**2026-09-19**: section 2's idempotency row is closed. A handler marked `@Idempotent()` now executes at most once per client-supplied `Idempotency-Key`: a retry with the same key and body replays the stored response instead of running the handler again, a reused key with a different body is rejected (422), and a concurrent retry while the first call is still running gets 409. The store is a port (`IdempotencyStorePort`) with two adapters selected by `IDEMPOTENCY_STORE` — an in-memory one for a single instance, and an Oracle one (a row per key, its unique index doubling as the claim lock) for a shared, restart-surviving store — because the in-memory adapter is useless for the exact scenario this feature exists for: a client retrying through a load balancer that might route the retry to a different instance. Full behaviour, configuration and the DDL: [Make an endpoint idempotent](guides/make-an-endpoint-idempotent.md). **This does not close the gap completely.** The interceptor claims the key, runs the handler, then completes it as three separate commits, not one transaction — a crash between the business write and the key being marked complete leaves the effect applied and the key still `in_progress`, and the eventual retry (once the in-progress TTL elapses) re-executes it. What shipped is at-most-once _responses_ under normal operation and best-effort at-most-once _effects_, not a transactional guarantee; the guide's stronger recipe (write the key row inside the use case's own `UnitOfWorkPort.run(...)`) is what closes that residual gap, per endpoint, when it matters enough to pay for it.

## 1. Defects and risks in what exists

Every row from the last review is closed by the pass described above, except pagination — which turned out not to be a defect at all. The dependency queue that used to be section 1's one open item is unstuck: eight of the nine Dependabot PRs (CI Actions to their latest majors, `@types/*`/`jest`/`@eslint/js` within range, and the `lint-and-format` major — the one that was red on `format:check`) are re-applied by hand on `chore/dependency-refresh`, and the ninth — `@nestjs/*` 11→12, the other red one — is investigated and deliberately deferred rather than forced.

**`@nestjs/*` 12 is deferred, and it is an upstream gap, not a design smell.** The original suspicion — that typed DI ([decision 0002](decisions/0002-typed-di-tokens.md)) was the seam breaking on every major bump — didn't hold up: `pino.module.ts` and `throttling.module.ts`'s `inject` arrays were never the problem. `@nestjs/common@12`'s new package `exports` map breaks the `@nestjs/common/interfaces` deep import that `nestjs-pino@4.4.1` and every published `@nestjs/throttler` (up to `6.7.0`, its latest) still use in their type declarations, and `@nest-lab/throttler-storage-redis@1.2.0` has no `@nestjs/common@^12` peer published at all. Full evidence trail and the revisit condition: [decision 0014](decisions/0014-nestjs-12-deferred.md). `.github/dependabot.yml` now ignores `@nestjs/*` majors so the PR stops reopening weekly until upstream catches up. The `lint-and-format` major (ESLint 10, Prettier 3.9) is applied; its stricter `no-unnecessary-type-assertion` and `no-base-to-string` rules caught two genuine issues — a `toString()` helper that used to accept a plain object and silently return `"[object Object]"`, and an exception-filter fallback with the same risk — both fixed, not suppressed.

**Pagination stays, and now has tests, but is still unproven end to end.** `shared/pagination` (`encodeCursor`/`decodeCursor`) and `interface/http/schemas/pagination.schema.ts` (`OffsetQuerySchema`, `CursorQuerySchema`) are deliberate out-of-the-box furniture for an example feature that hasn't been written yet, not dead code left by mistake. `test/unit/shared/pagination/cursor.spec.ts` and `test/unit/interface/http/schemas/pagination.spec.ts` now cover the encode/decode round trip, a truncated or tampered cursor being rejected outright instead of half-parsed, the offset/cursor boundary values, and the `orderBy` whitelist regex against a SQL-injection attempt. What they still can't prove is that a real repository or controller wires them up correctly — that only happens once the first paginated endpoint actually uses them.

Accepted on purpose, listed so nobody reports them as bugs: `/metrics` is unauthenticated when `METRICS_ENABLED=true` (a scraper has no token — keep the port on your monitoring network), and `/health` and `/health/ready` are public and unthrottled (a load balancer has neither a token nor patience).

## 2. Missing features

Things a production service usually needs that this template does not provide at all.

| #   | Missing                          | Why it matters                                                                                                                                                                                                                                                           | Note                                                                                   |
| --- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 1   | **Authorization beyond roles**   | `@Roles()` covers roles carried by the token. Roles or permissions stored in a database, and policies that depend on the resource, are documented ([guide](guides/add-an-auth-strategy.md)) but not provided: no permissions port, no cache, no policy model.            | Each project still writes that part                                                    |
| 2   | **JWKS / key rotation**          | Only static secrets and algorithms from config; `grep -rn "jwks" src` is empty. Keycloak, Entra ID and AD FS shops need `jwks_uri` with `kid` selection and caching.                                                                                                     | `src/infrastructure/auth/strategies/jwt.strategy.ts`                                   |
| 3   | **Caching**                      | `ioredis` is already a dependency for shared throttling, but there is no cache port, so repeated lookups (roles, reference data) hit the database every request.                                                                                                         | A small `CachePort` + Redis/in-memory adapters                                         |
| 4   | **Queues and a shipped outbox**  | The outbox is now a written recipe ([guide](guides/deliver-events-reliably.md)), not code, and cron is still the only background mechanism. No queue port, no outbox table, no processor.                                                                                | Cron jobs now drain cleanly on shutdown (section 0); a queue is still a separate build |
| 5   | **Database migrations**          | Nothing, not even a stated position for the case where you _do_ own the schema. The "database you don't own" guide covers the opposite case well.                                                                                                                        | Pick a tool and write one page, or say clearly it is out of scope                      |
| 6   | **A one-command test database**  | `docker-compose.yml` does ship `gvenzl/oracle-free` with a healthcheck, so the container is not the hard part — the missing pieces are a schema seed and wiring `pnpm test:oracle` to it. Today the live suite needs a database you prepared by hand, so it runs rarely. | That rarity is how a real bug (errors unmapped inside a unit of work) survived         |
| 7   | **Multi-tenancy**                | No tenant concept anywhere. The Oracle context user identifies the actor, not a tenant, and is not a data-scoping mechanism.                                                                                                                                             | Add deliberately if you need it; retrofitting is expensive                             |
| 8   | **Deprecation path for the API** | URI versioning works, but there is no `Deprecation`/`Sunset` header helper and no written policy for retiring a version.                                                                                                                                                 |                                                                                        |
| 9   | **Repository hygiene**           | No LICENSE, CONTRIBUTING, pull-request template, commit linting or pre-commit hook — in a repository whose whole purpose is to be forked. CI, Dependabot and a root `CHANGELOG.md` now exist, so the gap is narrower than it was.                                        | Conventions are enforced by reviewers and agents, not by tooling                       |

## 3. Opinions

Judgement calls rather than defects. Disagree freely — but disagree on purpose.

- **The documentation still outruns what is enforced.** Eighteen guides and eight decision records, all containing code that is never compiled. This is no longer a hypothetical: dropping `@nestjs/jwt` broke the e2e example in `write-tests.md` the same day, and nothing caught it — not the type-checker, not CI, not the coverage floor, only a human re-reading the file. Deleting a branch broke a second guide the same way. A test that extracts the TypeScript blocks and type-checks them would have failed on the first; a link/branch check would have caught the second. Until then, every dependency or branch change silently rots the pages agents copy from.
- **`shared` vs `common` vs `application/contracts`** is three buckets for cross-cutting code whose names don't say which is which, and the fence work just added a fourth address to learn (`@shared/metrics`). People will guess wrong. Merge them or rename them for what they are.
- **There are two routes from a failure to an HTTP status**: a returned `Result.err` handled by the interceptor, and a thrown error handled by the filter. Both are documented and both work; two code paths for one outcome still drift eventually.
- **The dialect placeholders promise portability the code doesn't have.** Five hand-written source schemas, one implemented client. Either implement a second dialect to prove the seam, or say plainly in the README that it is untested. (The lean sibling collapsed them to one passthrough shape, which is the cheaper half of this fix.)
- **The template is large for a small service** — 231 files before any business code, up from 150 two reviews ago, because every closed gap added code. That pays off for a team running several services and is heavy for a single-endpoint one. The answer now exists as a separate repository, `nestjs-ddd-lean`, rather than as a "what you can safely delete" note here.
- **Nothing syncs the two templates.** A fix made here (the pino meta-order bug, say) does not reach `nestjs-ddd-lean` unless someone applies it twice. If that starts to hurt, write a short decision record naming the files that are shared by convention and worth diffing occasionally.
- **What the template gets right**, for balance: layer boundaries that fail the build in all four layers now, typed DI tokens where a wrong binding doesn't compile, the context-user lifecycle, error-to-status mapping that never leaks internals, configuration that fails fast without printing secrets, and a shutdown sequence that was tested against a real `SIGTERM` rather than assumed.

## 4. What I'd fix first

Every defect from the last two reviews is closed, pagination was reclassified rather than fixed, and the dependency queue is unstuck (section 1), so section 1 holds nothing left to do — the one remaining item, `@nestjs/*` 12, is deliberately deferred with its revisit condition written down rather than open-ended.

Section 2, roughly in this order:

1. **Authorization beyond token roles** — `@Roles()` only reads what the issuer put in the token; permissions or policies stored in a database still need a project-specific guard.
2. **A queue or a shipped outbox** — the outbox is a written recipe, not code, and cron is still the only background mechanism.
3. **Caching** — `ioredis` is already a dependency for throttling, but there is no cache port, so repeated lookups hit the database every request.

Those are decisions about your platform, not gaps in this repository.

## Environment items (not code)

- The API container in `docker-compose.yml` has never been built or run here: Docker Desktop ran out of disk during the attempt, and the stack was used with Oracle in Docker and the API on the host.
- The Windows service scripts are checked in a PowerShell container (`pnpm test:service-scripts`); registering the service on a real Windows machine is still unverified.
- The live Oracle suite (`pnpm test:oracle`) and the service-script suite are not part of `pnpm verify` and did not run during this review.
- `main` is pushed and CI is green on it. The nine open Dependabot pull requests as of 2026-09-19 cannot be merged directly — they're based on an older commit and their diffs delete the idempotency feature — so their bumps were re-applied by hand on `chore/dependency-refresh` instead: eight land (the four CI Actions bumps, `@types/*`, `jest`, `@eslint/js`, and the `lint-and-format` major), and `@nestjs/*` is deliberately deferred with its revisit condition recorded ([decision 0014](decisions/0014-nestjs-12-deferred.md)) and a matching `ignore` entry in `dependabot.yml`. Once that branch merges, all nine Dependabot PRs should be closed unmerged rather than merged.
