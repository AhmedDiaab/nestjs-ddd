# Known gaps and open items

An honest, dated review of what this template **does not** do, what is weak in what it does do, and what I'd fix first. Kept in the repo so a team adopting the template inherits the list instead of rediscovering it in production.

- **Reviewed**: 2026-09-18, against `feat/oracle-backport` (`18d302e`), re-read layer by layer.
- **Size at that commit**: 221 source files, ~6,130 lines, 26 runtime dependencies, 50 spec files, coverage floor 85/70/71/85.
- **Scope**: the template itself. Business features built on top are out of scope.
- **How to use it**: before starting a project from this template, walk sections 1 and 2 and decide per row — fix it, accept it, or replace it with your platform's version. Cross items off as you go; delete the ones that don't apply to you.

Terms: [Glossary](glossary.md). Rules the template does enforce: [Architecture overview](architecture/overview.md).

## 0. Closed since the first review

**2026-09-18, first pass**: the `Hello World` scaffolding is gone and `AppModule` is now only a composition root. Correlation ids from outside are validated before they reach the logs, and both the request id and the W3C `traceparent` come back as response headers ([Observability](architecture/observability.md)). Shutdown fails readiness first, keeps serving while the load balancer notices, drains in-flight requests and closes the database pools last ([Operations](architecture/operations.md#graceful-shutdown)). Authentication used to be opt-in per controller; `JwtGuard` is now a global `APP_GUARD` with a `@Public()` opt-out ([guide](guides/add-an-auth-strategy.md)). Metrics, tracing, an outbound HTTP client with retries and a circuit breaker, CI on every pull request and a coverage floor all landed.

**2026-09-18, second pass**: the interface layer is fenced — `src/interface/**` cannot import `@infrastructure` at all, enforced by ESLint and kept honest by `test/unit/layers/interface-fence.spec.ts`. `HealthController` goes through a new `DatabaseHealthPort` instead of reaching for `ConnectionProviderToken`. `GET /health/ready` answers `{status}` only; the per-source topology moved to an authenticated `GET /v1/health/sources` (`@Roles('admin')`), with failing sources logged at `warn`. Domain event delivery states its guarantee in the port JSDoc and counts `domain_events_published_total` / `domain_event_handler_failures_total`, so a handler that always throws is visible on a dashboard; [the outbox recipe](guides/deliver-events-reliably.md) covers events another system depends on. The rate limiter finally has an e2e proving it returns 429.

## 1. Defects and risks in what exists

Ordered by how much damage they can do. Smaller than it used to be, and none of these is architectural.

| #   | Gap                                                                                                                                                                                                                                                                                                                                   | Where                                                                                        | Suggested fix                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | **A scheduled job in flight is not drained on shutdown.** `runGracefulShutdown` drains the HTTP server, then closes the app — which closes the database pools. `JobRunner` only prevents overlapping runs; nothing waits for the current run, so a job writing to Oracle when `SIGTERM` arrives loses its connection mid-transaction. | `src/infrastructure/lifecycle/graceful-shutdown.ts`, `src/interface/scheduler/job-runner.ts` | Either await the in-flight run before `closeApp()`, or state in the guide that every job must be safe to kill and re-run |
| 2   | **`@nestjs/jwt` is a runtime dependency used only by tests.** `src/` verifies tokens with `passport-jwt` and never signs one; the only importers are three e2e specs.                                                                                                                                                                 | `package.json:40`                                                                            | `pnpm remove @nestjs/jwt && pnpm add -D @nestjs/jwt`, or sign test tokens with `node:crypto` as the lean sibling does    |
| 3   | **The pagination helpers have no consumers at all.** `shared/pagination`, `application/contracts/paginated-repository.ts` and `interface/http/schemas/pagination.schema.ts` are exported from their barrels and imported by nothing, so nobody knows whether they work end to end.                                                    | three files, zero call sites                                                                 | Use them in the example endpoint, or delete them and let each project write its own                                      |
| 4   | **One dead line of wiring reads as load-bearing.** `ThrottlingModule` re-exports `ThrottlerModule`, but `@nestjs/throttler` marks its own module `@Global()`, so the export does nothing. Removing it changes no behaviour — which was proven by mutation, not by reading.                                                            | `src/infrastructure/throttling/throttling.module.ts:33`                                      | Drop `ThrottlerModule` from `exports`; keep `ThrottlerStorageToken`, which genuinely is load-bearing                     |

Accepted on purpose, listed so nobody reports them as bugs: `/metrics` is unauthenticated when `METRICS_ENABLED=true` (a scraper has no token — keep the port on your monitoring network), and `/health` and `/health/ready` are public and unthrottled (a load balancer has neither a token nor patience).

## 2. Missing features

Things a production service usually needs that this template does not provide at all.

| #   | Missing                          | Why it matters                                                                                                                                                                                                                                                           | Note                                                                           |
| --- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 1   | **Authorization beyond roles**   | `@Roles()` covers roles carried by the token. Roles or permissions stored in a database, and policies that depend on the resource, are documented ([guide](guides/add-an-auth-strategy.md)) but not provided: no permissions port, no cache, no policy model.            | Each project still writes that part                                            |
| 2   | **JWKS / key rotation**          | Only static secrets and algorithms from config; `grep -rn "jwks" src` is empty. Keycloak, Entra ID and AD FS shops need `jwks_uri` with `kid` selection and caching.                                                                                                     | `src/infrastructure/auth/strategies/jwt.strategy.ts`                           |
| 3   | **Caching**                      | `ioredis` is already a dependency for shared throttling, but there is no cache port, so repeated lookups (roles, reference data) hit the database every request.                                                                                                         | A small `CachePort` + Redis/in-memory adapters                                 |
| 4   | **Idempotency**                  | No idempotency keys and no dedupe store. Clients retrying through a load balancer will execute a POST twice — and the outbound client will not retry a POST for exactly this reason, so the asymmetry is visible in the template itself.                                 | Matters with the VIP setups in the migration guide                             |
| 5   | **Queues and a shipped outbox**  | The outbox is now a written recipe ([guide](guides/deliver-events-reliably.md)), not code, and cron is still the only background mechanism. No queue port, no outbox table, no processor.                                                                                | See also row 1 in section 1: jobs are not drained                              |
| 6   | **Database migrations**          | Nothing, not even a stated position for the case where you _do_ own the schema. The "database you don't own" guide covers the opposite case well.                                                                                                                        | Pick a tool and write one page, or say clearly it is out of scope              |
| 7   | **A one-command test database**  | `docker-compose.yml` does ship `gvenzl/oracle-free` with a healthcheck, so the container is not the hard part — the missing pieces are a schema seed and wiring `pnpm test:oracle` to it. Today the live suite needs a database you prepared by hand, so it runs rarely. | That rarity is how a real bug (errors unmapped inside a unit of work) survived |
| 8   | **Multi-tenancy**                | No tenant concept anywhere. The Oracle context user identifies the actor, not a tenant, and is not a data-scoping mechanism.                                                                                                                                             | Add deliberately if you need it; retrofitting is expensive                     |
| 9   | **Deprecation path for the API** | URI versioning works, but there is no `Deprecation`/`Sunset` header helper and no written policy for retiring a version.                                                                                                                                                 |                                                                                |
| 10  | **Repository hygiene**           | No LICENSE, CHANGELOG, CONTRIBUTING, pull-request template, commit linting or pre-commit hook — in a repository whose whole purpose is to be forked. CI and Dependabot now exist, so the gap is narrower than it was.                                                    | Conventions are enforced by reviewers and agents, not by tooling               |

## 3. Opinions

Judgement calls rather than defects. Disagree freely — but disagree on purpose.

- **The documentation still outruns what is enforced.** Fifteen guides and eight decision records, all containing code that is never compiled. One snippet was broken until someone read it closely, and agents copy from these pages. A test that extracts the TypeScript blocks and type-checks them would keep them honest; without it they rot quietly. Two stale references were found and fixed by hand during this pass — that is the failure mode, repeating.
- **`shared` vs `common` vs `application/contracts`** is three buckets for cross-cutting code whose names don't say which is which, and the fence work just added a fourth address to learn (`@shared/metrics`). People will guess wrong. Merge them or rename them for what they are.
- **There are two routes from a failure to an HTTP status**: a returned `Result.err` handled by the interceptor, and a thrown error handled by the filter. Both are documented and both work; two code paths for one outcome still drift eventually.
- **The dialect placeholders promise portability the code doesn't have.** Five hand-written source schemas, one implemented client. Either implement a second dialect to prove the seam, or say plainly in the README that it is untested. (The lean sibling collapsed them to one passthrough shape, which is the cheaper half of this fix.)
- **The template is large for a small service** — 221 files before any business code, up from 150 at the last review, because every closed gap added code. That pays off for a team running several services and is heavy for a single-endpoint one. The answer now exists as a separate repository, `nestjs-ddd-lean`, rather than as a "what you can safely delete" note here.
- **Nothing syncs the two templates.** A fix made here (the pino meta-order bug, say) does not reach `nestjs-ddd-lean` unless someone applies it twice. If that starts to hurt, write a short decision record naming the files that are shared by convention and worth diffing occasionally.
- **What the template gets right**, for balance: layer boundaries that fail the build in all four layers now, typed DI tokens where a wrong binding doesn't compile, the context-user lifecycle, error-to-status mapping that never leaks internals, configuration that fails fast without printing secrets, and a shutdown sequence that was tested against a real `SIGTERM` rather than assumed.

## 4. What I'd fix first

1. Decide what a `SIGTERM` means for a running job (section 1, row 1). It is the only item left that can corrupt data.
2. Move `@nestjs/jwt` to `devDependencies` — one line, and the production image stops shipping a package that verifies nothing.
3. Use the pagination helpers in the example feature or delete them. Unused code in a template is worse than absent code: people copy it assuming it works.
4. Then pick from section 2 in this order: authorization beyond token roles, idempotency, a queue or shipped outbox, caching. Those are decisions about your platform, not gaps in this repository.

## Environment items (not code)

- The API container in `docker-compose.yml` has never been built or run here: Docker Desktop ran out of disk during the attempt, and the stack was used with Oracle in Docker and the API on the host.
- The Windows service scripts are checked in a PowerShell container (`pnpm test:service-scripts`); registering the service on a real Windows machine is still unverified.
- The live Oracle suite (`pnpm test:oracle`) and the service-script suite are not part of `pnpm verify` and did not run during this review.
